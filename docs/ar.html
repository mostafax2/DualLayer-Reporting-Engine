المشكلة

عندما تُثقل التقارير قاعدة البيانات

مع ملايين السجلات، يتحوّل كل استعلام تحليلي إلى عبء حقيقي على الـ production database.

🗄️  bpe_tasks 10,000,000+ rows
id1,000,001
⏳ JOIN users ON...5.2s
⏳ GROUP BY type8.1s
⏳ AVG(duration)...12.4s
......
-- يُنفَّذ مع كل فتح للـ Dashboard SELECT type, AVG(TIMESTAMPDIFF(...)) FROM bpe_tasks JOIN users ON ... WHERE tenant_id = ? GROUP BY type, DATE(created_at) ORDER BY avg_duration DESC;
⏱ 12.4 ثانية — لكل طلب!
  • استعلامات تحليلية بطيئة على ملايين السجلات
  • الـ MySQL تتحمل ضغطاً مزدوجاً: كتابة وقراءة في آنٍ واحد
  • JOIN بين 5-6 جداول في كل طلب dashboard
  • حساب TIMESTAMPDIFF على كل صف في كل مرة
  • الـ scaling صعب — الـ read-replica لا تحل مشكلة الـ aggregation
  • تجربة المستخدم تتأثر سلباً بعمليات الـ reporting
الحل

كيف تعمل DualLayer

كل تغيير في الـ model يُنقل تلقائياً إلى MongoDB — حيث تتوفر نسخة محسوبة ومُهيَّأة للقراءة والتحليل.

MySQL

تغيير في الـ Model

أي create() أو update() أو delete() — يرصده الـ package تلقائياً.

١
٢
Observer

Observer يلتقط الحدث

ModelSyncObserver يُفعَّل تلقائياً، ويُنشئ ModelReference بـ sync_id محسوب باستخدام hash.

Queue

Job في الـ Queue

ProcessSyncJob يُرسَل إلى queue منفصل — الـ HTTP response لا يتأخر أبداً.

٣
٤
SyncEngine

SyncEngine يعالج

يتحقق من الـ idempotency، يسحب أحدث البيانات من MySQL، يحوّلها بالـ Transformer، ثم يكتبها في MongoDB.

MongoDB

Document محسوب جاهز

نسخة مُحسَّنة للتحليل: duration_ms محسوبة مسبقاً، has_error جاهزة، الـ nested fields مُجمَّعة — بدون أي JOIN.

٥
٦
Analytics API

Dashboard سريع ⚡

الـ analytics endpoint يقرأ من MongoDB بـ aggregation pipelines — بدون JOIN، بدون TIMESTAMPDIFF، دون أي تأثير على MySQL.

المميزات

كل ما تحتاجه — موجود

🔐

Idempotency مضمونة

إذا أُرسل نفس الـ job مرتين، يُعالَج مرة واحدة فقط. الـ sync_id = hash من (model + id + operation + updated_at).

🔄

Retry تلقائي

في حال فشل الاتصال بـ MongoDB، يُعيد الـ package المحاولة تلقائياً بـ exponential backoff: 30s ← 90s ← 270s، ثم Dead Letter.

🎛️

Transformers قابلة للتخصيص

ليست مجرد نسخ — بل تحسب fields مُشتقة قبل الكتابة إلى MongoDB: duration_ms، size_mb، has_error، وأي حقل آخر.

🪝

Lifecycle Hooks

beforeSync لإيقاف الـ sync عند الحاجة، afterSync لتنظيف الـ cache أو إرسال notification.

📡

Domain Events

اشترك في SyncCompleted، SyncFailed، SyncRetried، SyncDead — وأضف alerts أو metrics دون المساس بالـ core.

🏢

Multi-tenant Ready

الـ tenant_id يتدفق عبر كامل الـ pipeline — من الـ Observer إلى MongoDB وصولاً إلى الـ analytics query — تلقائياً.

🔌

Architecture نظيفة

Hexagonal Architecture — كل مكوّن خلف Interface. تغيير الـ target من MongoDB إلى Elasticsearch بسطر واحد في الـ config.

📋

Audit Trail كامل

جدول dlr_sync_operations بيسجّل كل عملية: status، attempts، errors، timings — للـ debugging والمراجعة.

⚡

Stateless Workers

الـ workers لا يتشاركون أي state — scale أفقياً دون الحاجة لأي coordination. كل worker مستقل تماماً.

Reliability

Developer Experience

سطرين يكفيان

التكامل الكامل يتم في AppServiceProvider — دون الحاجة لتعديل أي model أو controller.

// AppServiceProvider.php — هذا كل ما تحتاجه public function boot(): void { // User بدون transformer خاص → DefaultTransformer DualReport::observe(User::class); // Order مع transformer مخصص DualReport::register(Order::class, new OrderTransformer()); // ProcessingTask مع transformer + hooks DualReport::register(ProcessingTask::class, new TaskTransformer()) ->hooks(new TaskSyncHooks()); }
class TaskTransformer implements TransformerInterface { public function handles(): string { return ProcessingTask::class; } public function collection(): string { return 'processing_tasks'; } public function documentKey(): string { return 'task_id'; } public function sourceKey(): string { return 'id'; } public function transform(array $attr): array { return [ 'task_id' => $attr['id'], 'type' => $attr['type'], 'status' => $attr['status'], // حسابات تُجرى مرة واحدة وتُخزَّن — لا تُكرَّر في كل query 'duration_ms' => $this->diffMs($attr['started_at'], $attr['completed_at']), 'has_error' => !empty($attr['error_message']), 'file' => [ 'name' => $attr['original_filename'], 'size_mb' => round($attr['file_size'] / 1048576, 2), ], ]; } }
class TaskSyncHooks implements SyncHooksInterface { public function handles(): string { return ProcessingTask::class; } // قبل الكتابة — يمكن إيقاف الـ sync public function beforeSync(string $op, array $doc): bool { // لا تُزامن task منتهية الصلاحية قبل بدء معالجتها if ($doc['status'] === 'pending' && $doc['attempts'] === 0) { return !$this->isExpired($doc); } return true; } // بعد الكتابة — تنظيف الـ cache public function afterSync(string $op, array $doc): void { Cache::forget("stats:tenant:{$doc['tenant_id']}"); } }
// EventServiceProvider.php — اشترك في أحداث الـ sync protected $listen = [ SyncDead::class => [AlertOpsTeam::class], SyncFailed::class => [LogSyncError::class], ]; // AlertOpsTeam.php public function handle(SyncDead $event): void { Log::channel('slack')->critical('Dead Letter!', [ 'model' => $event->model->modelClass, 'id' => $event->model->modelId, 'attempts' => $event->totalAttempts, 'error' => $event->lastError, ]); }
